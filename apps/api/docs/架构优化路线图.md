### 1.3 API 客户端导出重构 ✅

**状态**: 已完成

**改动文件**:
- `apps/web/lib/api/contracts/client.ts` - 重构为工厂函数模式

**重构成果**:
- 代码量: 629 行 → 541 行 (-14%)
- 新增工厂函数 `createApiClient()` 统一创建 Direct Client 和 React Query Client
- 保持向后兼容，所有旧导出使用 `@deprecated` 标记
- 新增 contract 只需一行: `export const xxx = createApiClient(xxxContract);`

**新用法**:
```typescript
// 推荐: 使用新导出
import { bot } from '@/lib/api/contracts/client';
bot.client.getBot({ params: { id: '123' } }); // Direct call
bot.query.getBot.useQuery({ params: { id: '123' } }); // React Query

// 兼容: 旧导出仍可用 (带 @deprecated 警告)
import { botClient, botApi } from '@/lib/api/contracts/client';
```

## 二、待完成的优化

### 2.1 TypeScript 严格模式迁移 🔴 高优先级

**当前状态**:
```json
{
  "strict": false,
  "strictNullChecks": false,
  "noImplicitAny": false
}
```

**目标**: 启用完整严格模式

**实施步骤**:

| 阶段 | 配置 | 预估工作量 |
|------|------|------------|
| Phase 1 | `strictNullChecks: true` | 1-2 天 |
| Phase 2 | `noImplicitAny: true` | 1-2 天 |
| Phase 3 | `strict: true` | 2-3 天 |

**风险**: 可能需要修改大量代码以修复类型错误

---

### 2.2 清理 no-unused-vars 警告 🟡 中优先级

**当前状态**: 214 个警告

**高发文件**:

### 2.3 Domain 层结构优化 🟢 低优先级

**当前状态**:
```
libs/domain/
├── auth/
└── services/
    └── ip-info/
```

**问题**: DB Service 放在 `generated/db/` 而非 `libs/domain/db/`

**建议**:
- 保持现状（命名约定明确）
- 或重命名 `generated/db` → `libs/domain/db`

## 三、架构审查总结

### 3.1 架构优点 ✅

1. **清晰的 Monorepo 结构** - pnpm workspaces + Turborepo
2. **良好的后端分层** - API → Service → DB Service → Prisma
3. **类型安全的 API** - ts-rest + Zod 4
4. **事务管理设计** - TransactionalServiceBase + UnitOfWork

### 3.2 需要改进 ⚠️

| 问题 | 影响 | 优先级 |
|------|------|--------|
| TypeScript 严格模式未启用 | 运行时类型错误 | 🔴 高 |
| console.log 使用过多 | 日志不统一 | ✅ 已修复 |
| API 客户端重复代码 | 维护困难 | 🟡 中 |
| Service 层架构违规 | 违反分层原则 | 🟡 中 |
| 大量 no-unused-vars | 代码质量 | 🟡 中 |
