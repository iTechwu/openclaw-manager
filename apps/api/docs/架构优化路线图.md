### 2.3 API 客户端导出重构 🟡 中优先级

**当前状态**: 629 行重复代码

**重构方案**: 使用工厂函数

```typescript
// 重构前 (重复 25+ 次)
export const botClient = initClient(botContract, clientOptions);
export const botApi = initQueryClient(botContract, clientOptions);

// 重构后
export const bot = createApiClient(botContract);
// 使用: bot.client (imperative), bot.query (React Query)
```

**迁移注意事项**:
- 现有代码使用 `tsRestClient.message.list.useQuery()` 格式
- 重构后需要更新所有使用点，或保持 `tsRestClient` 的向后兼容
- 建议: 分两阶段迁移
  1. Phase 1: 新增工厂函数，保持现有导出
  2. Phase 2: 逐步迁移使用点到新格式

**预期效果**:
- 代码量: 629 行 → ~350 行 (最终)
- 维护性: 新增 contract 只需一行

### 2.4 Service 层架构违规修复 🟡 中优先级

**发现的问题**:

| 文件 | 违规类型 | 严重性 |
|------|----------|--------|
| `bot-usage-analytics.service.ts` | 直接注入 PrismaService | 🔴 高 |

**修复方案**:

```typescript
// 违规代码
@Injectable()
export class BotUsageAnalyticsService {
  constructor(private readonly prisma: PrismaService) {}
  
  async getStats() {
    return this.prisma.read.botUsageLog.aggregate({...});
  }
}

// 修复后
@Injectable()
export class BotUsageAnalyticsService {
  constructor(private readonly botUsageLogService: BotUsageLogService) {}
  
  async getStats() {
    return this.botUsageLogService.aggregate({...});
  }
}
```

### 2.5 Domain 层结构优化 🟢 低优先级

**当前状态**:
```
libs/domain/
├── auth/
└── services/
    └── ip-info/
```

**建议**:

- 或重命名 `generated/db` → `libs/domain/db`

---

### 2.6 环境变量管理优化 🟢 低优先级

**当前状态**: 多处直接使用 `process.env`

**建议**:
- 使用 `@nestjs/config` 的 `ConfigService` 统一管理
- 添加环境变量验证 schema

## 三、架构审查总结

### 3.1 架构优点 ✅

1. **清晰的 Monorepo 结构** - pnpm workspaces + Turborepo
2. **良好的后端分层** - API → Service → DB Service → Prisma
3. **类型安全的 API** - ts-rest + Zod 4
4. **事务管理设计** - TransactionalServiceBase + UnitOfWork

### 3.2 需要改进 ⚠️

| 问题 | 影响 | 优先级 |
|------|------|--------|
| TypeScript 严格模式未启用 | 运行时类型错误 | 🔴 高 |
| console.log 使用过多 | 日志不统一 | ✅ 已修复 |
| API 客户端重复代码 | 维护困难 | 🟡 中 |
| Service 层架构违规 | 违反分层原则 | 🟡 中 |
| 大量 no-unused-vars | 代码质量 | 🟡 中 |
